Retrieval, 5 minutes, no notes: A2.3 and A2.1.4

Four quick ones

1. What does NAT do on a home router?

Translates the private IP addresses of the devices inside into the router's one public IP address, and keeps a table so replies go back to the right device.

2. Name two things a packet's header carries.

Any two: source IP address, destination IP address, sequence number, protocol, (also a checksum, time to live).

3. Is 192.168.1.24 a public or a private address? Can a server on the internet send a packet straight to it?

Private. No: private addresses are not routed on the internet. The packet has to go to the router's public address.

4. What is the difference between HTTP and HTTPS?

HTTPS is HTTP with encryption (TLS): anyone on the path sees only scrambled data. HTTP sends everything as plain text.

Port numbers: which program a packet is for

An IP address gets a packet to the right device. A port number gets it to the right program on that device.

A2.4.1 Firewalls: what and where

A checkpoint at the edge of the network

A firewall inspects every packet going in or out and applies rules to decide: allow it or block it.

Hardware

A dedicated box at the boundary between the internet and the LAN. Protects the whole network. Schools, businesses, data centers.

Software

Runs on one computer (Windows Defender Firewall, macOS firewall). Protects only that device, wherever it goes.

Next-generation

Combines all the inspection techniques on the next slide, plus intrusion prevention. The standard in organizations today.

A2.4.1 Firewalls: the rules

Whitelist, blacklist, custom rules

Whitelist

Only traffic on the list is allowed. Everything else is blocked.

Example: only the partner company's IP addresses may reach the database server.

Blacklist

Traffic on the list is blocked. Everything else is allowed.

Example: block the addresses of known botnet servers.

Custom rules

Any mix of conditions on IP address, port, protocol and direction.

Example: allow port 443 to the web server; block port 23 from everywhere.

Order matters

Rules are checked from top to bottom. The first rule that matches decides. The last rule is usually "block everything else": a default deny policy.

Which is more secure, a whitelist or a blacklist? Why?

A whitelist. It is default deny: a brand-new attack is blocked because it is not on the allowed list. A blacklist only stops threats someone already knows about and has listed. The cost: a whitelist is less flexible and blocks legitimate traffic nobody thought to add.

A2.4.1 The role of NAT: you met NAT in A2.3, now see it as security

No table entry, no way in

A reply comes in only if a device inside asked first. An unsolicited packet has no NAT table entry, so the router has nowhere to send it and drops it.

Hides the inside

The internet sees one public address. It cannot see that 45 devices sit behind it, or their addresses.

Blocks unsolicited inbound connections

Nothing outside can start a connection to a private address.

Smaller attack surface

Private addresses cannot be targeted directly from the internet.

So is NAT a firewall?

No. NAT never inspects traffic. Malware inside can still connect out, and an attack hidden in a normal web reply passes straight through. Port forwarding can also open a way in on purpose. NAT plus a firewall is stronger than either alone.

Where does NAT give no protection at all?

Against threats from inside the network (insiders, infected devices), and against anything in traffic that a device inside asked for.

A2.4.1 Discuss: what a firewall stops and what it does not, 6 minutes

Can the firewall stop it? Yes, partly or no

Someone outside scans the school for open ports

Yes. Unrequested inbound connections to closed ports are dropped.

Traffic from a known botnet address

Yes. A blacklist rule blocks the address.

An infected laptop tries to contact the attacker's server

Partly. Outbound rules can block known bad addresses, not new ones.

A virus arrives inside a download

Partly. DPI can spot known malware; new malware gets through.

A phishing email asks a teacher for their password

No. It is ordinary email on an allowed port; the firewall cannot see deception.

A staff member copies student records to a USB stick

No. The insider is already inside; no packet crosses the firewall.

Malware hidden in an HTTPS download

Limited. The payload is encrypted; only DPI with TLS inspection can look.

Attackers use an unknown flaw in the firewall itself

No. The checkpoint becomes the way in (ArcaneDoor, see the real cases).

Strong against known, rule-based threats from outside. Weak against people, insiders and the unknown.

Real cases: reading in your copy of the deck

When the checkpoint fails

WannaCry, May 2017

Ransomware spread through a Windows file-sharing flaw. Organizations whose firewalls blocked that service from outside cut their exposure. Unpatched, flat networks did not: over 80 NHS organizations hit, appointments canceled, recovery over £90 million.

Lesson: a well-configured firewall helps; it does not replace patching and segmentation.

ArcaneDoor, 2024

Attackers used zero-day flaws in Cisco firewall devices. The compromised firewalls kept looking normal while copying traffic to the attackers and surviving reboots.

Lesson: the firewall is software too. Update it, monitor it, and never treat it as the only layer.

Exam technique, 2 minutes

Discuss means both sides, then a judgment

Discuss the effectiveness of a firewall at protecting a school network. [6]

For: what it does well

Two developed points. For example: it blocks unrequested connections from outside by filtering on IP address, port and protocol, so port scans and direct attacks fail.

Against: what it misses

Two developed points. For example: phishing email arrives on an allowed port, so it passes; a staff member copying data is already inside.

Judgment

A clear conclusion. For example: essential for known outside threats, not enough alone, so the school also needs training, patching and encryption (defense in depth).

One-sided answers lose marks, however good the side.

A2.4.4 Encryption: the second half

Plaintext, key, ciphertext

Encryption uses an algorithm and a key to turn readable plaintext into ciphertext. Only someone with the right key can turn it back.

Try it: a Caesar cipher (the key is the shift)

Encryption gives you

Confidentiality: it stays secret.

Integrity: you can tell if it was changed.

Authenticity: it really came from who it claims.

The Caesar cipher has only 25 keys, so a computer tries them all at once (a brute-force attack). Real keys are 128 or 256 bits long: more possible keys than there are atoms in the observable universe, for 256 bits.

A2.4.4 Symmetric encryption

One shared key locks and unlocks

Strength

Very fast. Good for large amounts of data: whole disks, video, databases, Wi-Fi traffic.

Example

AES with 128 or 256-bit keys (banks, WPA3 Wi-Fi, BitLocker, cloud storage).

Weakness: the key distribution problem

Both sides need the key first. Send it over the internet and anyone who intercepts it can read everything.

A class of 20 wants every pair to have its own secret key. How many keys is that?

190 (20 × 19 ÷ 2). Shared keys grow fast with the number of people, and every one has to be delivered secretly. That is why symmetric keys alone do not work on the internet.

A2.4.4 Asymmetric encryption (public-key cryptography)

A key pair: one public, one private

Public key

Shared with anyone. Used to encrypt data for its owner.

Private key

Never shared. The only key that can decrypt it. Security depends on keeping it secret.

Trade-off

Solves key distribution, but much slower than symmetric. Example: RSA.

It also works the other way round: digital signatures

Alice signs with her own PRIVATE key. Anyone checks the signature with her PUBLIC key. If it checks out, only Alice could have signed it (authenticity) and nothing was changed since (integrity). Certificate Authorities sign certificates this way.

A2.4.4 Digital certificates, 5 minutes

Proof that this public key belongs to this website

Without certificates, an attacker in the middle could hand you their own public key and pretend to be the bank. A certificate is issued by a trusted Certificate Authority (CA), which checks who the owner is and signs the certificate with its private key.

    A2.4.4 Encryption key management, 3 minutes

    The algorithm can be perfect. The keys still need looking after

    Generation

    Truly random, long enough.

    If not: keys can be guessed or brute-forced.

    Storage

    Locked away, for example in a hardware security module, never next to the data.

    If not: steal the key, read everything (Heartbleed, 2014, leaked keys from server memory).

    Distribution

    Only over secure channels, using asymmetric methods and certificates.

    If not: an intercepted key opens all past and future messages.

    Rotation

    Replaced regularly; certificates expire (about 13 months at most).

    If not: a silently stolen key stays useful for years.

    Revocation

    Compromised certificates canceled at once (revocation lists, OCSP).

    If not: attackers keep impersonating the owner (DigiNotar, 2011: fake certificates worked for days).

    Destruction

    Old keys securely erased.

    If not: old data can be decrypted later.

    Encryption is only as strong as the way its keys are managed.

    Wrap-up and homework, 4 minutes

    Back to the three questions

    What will always get past a firewall?

    People (phishing), insiders, the unknown (zero-days), and anything it cannot read (encrypted payloads).

    How do two strangers talk in secret?

    Asymmetric encryption sets up a shared secret without sending it; fast symmetric encryption then protects the data.

    How does the browser know it is the real bank?

    The bank's certificate, signed by a CA the browser trusts, binds the bank's public key to its domain.
