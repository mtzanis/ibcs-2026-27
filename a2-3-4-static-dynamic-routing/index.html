Step 3, 2 minutes: the big question

Who fills in the routing table?

Static routing

A person types every route by hand.

The table stays the same until someone edits it.

Dynamic routing

The routers fill it in themselves.

They share what they know, and update the table when the network changes.

Common exam mistake: "static routing has no routing table". Wrong. Both use a table. The difference is who writes it and whether it updates by itself.
Static routing, 4 minutes: how it works

Static routing: typed by hand, fixed

1An administrator (the person who runs the network) logs in to each router.
2For each destination, they type the next hop.
3The table stays exactly as typed.
4Packets always follow those fixed routes, whatever happens.

Think: step 4 is both its biggest strength and its biggest weakness. Why? Strength: you always know the path. Weakness: if that path breaks, packets keep going there.

Static routing, 4 minutes: good and bad

Every point has a "because"

Predictable, because the routes never change by themselves.
Uses almost no router resources (processing, memory, bandwidth), because routers send no extra messages and do no route calculations.
Simple on a small network, because there are only a few routes to type.
Harder to fool, because routers do not accept routes from other routers.
Does not adapt: if a link fails, packets keep going to it until a person edits the table.
Lots of manual work: every change means editing the routers by hand.
Does not scale: more routers means more routes to type, and more mistakes.
Dynamic routing, 6 minutes: how it works

Dynamic routing: the routers talk to each other

1Each router tells its neighbors which networks it can reach, and the cost.
2From those messages, every router builds its own table.
3Packets go along the best current path (lowest cost).
4If a link breaks, the routers find out, recalculate, and send traffic another way.
New word Neighbor: a router directly connected to this one.
New word Routing protocol: the rules routers use to share routes. Names you may meet: RIP, OSPF. You do not need to know how they work.

Convergence, 4 minutes: the one new idea dynamic routing brings

The short wobble after a change

BeforeAll tables agree. Packets arrive.
Link breaksSome routers know, some do not yet.
ConvergingRouters swap messages. Tables disagree. Packets can be lost or go in circles.
ConvergedAll tables agree again, using the new path.
New word Convergence: the time it takes all routers to agree on the routes again after a change. Faster convergence = less disruption.

Does static routing have a convergence time?

No: there is nothing to converge, because the routers never update by themselves. But that also means it never recovers by itself: the outage lasts until a person fixes the table.

Routing challenge, 14 minutes, in pairs

Static, dynamic, or both? Give two factors.

Ask three questions: 1. Is it big, or will it grow? 2. Must it keep working by itself if a link breaks? 3. Is it small, stable, or must every path be tightly controlled?

1. Small office

20 computers, a printer, a file server. Must be simple and cheap.

Static. Small and stable (network size); few routes, no overhead (resource usage, complexity).

2. Online shop

Its web server must stay up even if a link or router fails.

Dynamic. Reroutes by itself after a failure, so it keeps working when something breaks (convergence); no waiting for a person.

3. University campus

Hundreds of devices, many departments, keeps growing.

Dynamic. Scalability and maintenance: new networks are learned automatically.

4. Bank vault systems

Traffic must follow exact, checked paths only.

Static. Predictable and easy to check, does not accept routes from other routers (security).

5. Hospital

Secure medical systems plus a big general network across buildings.

Both. Static for the secure systems (control); dynamic for the general network (scales, survives failures).

Exam technique, 3 minutes

Explain = give the because

Explain why static routing suits a small, stable network but not a large, changing one. [4]

Answer A

"Static is manual and dynamic is automatic, so static is for small networks."

1 mark at most: it never says why.

Answer B

"A small, stable network has few routes, so typing them by hand is easy, and static routing sends no routing messages. A large network has many routes, so the manual work and mistakes grow. Static routes also do not adapt, so a failed link breaks the path until someone edits the table."

4 marks: two reasons for small, two for large, each with a because.

Wrap-up and homework, 3 minutes: who writes the map?

Back to the four key questions

Where does the table come from?

Static: a person types it. Dynamic: the routers build it by sharing routes with their neighbors.

A link fails. Then what?

Static: packets keep going to the broken link until a person edits the table. Dynamic: the routers converge and reroute by themselves.

Why is typing routes a problem as a network grows?

More routers means more routes to type and keep up to date, and more mistakes: it does not scale.

What does dynamic routing cost?

Router resources (processing, memory, bandwidth), more complexity, and convergence time after a change.
