Toolkit part 1, 5 minutes: how data actually travels

Two ideas you need before the attacks

1. Addresses and packets (full detail in A2.3)

Every device on a network has an IP address. Data is split into packets. Each one carries where it came from and where it is going, and it passes through other devices (the Wi-Fi access point, routers) on the way.

From192.168.1.24
To151.101.0.81
Payload: the data itselffor example, your password

2. Encryption (full detail in A2.4.4)

Encryption scrambles the payload so that only a device with the right key can turn it back into readable data. Anyone else on the path sees nonsense.

HTTPS is HTTP with encryption (TLS). HTTP has none: the payload travels as plain text.

Who can read an HTTP payload on café Wi-Fi?

Any device the packets pass through, or anyone listening on the same Wi-Fi.

A server answers every packet it receives. Why could that be a problem?

Send it far more packets than it can answer and real users get nothing.

Toolkit part 2, 3 minutes: what a web page really is

Two more ideas, for the web attacks

3. Scripts in web pages

A web page is not just text. It can contain scripts (small JavaScript programs) that your browser runs automatically as soon as the page loads. You never click "run".

4. Session cookies

After you log in, the site gives your browser a session cookie: a token that says "this is Maya, already logged in". Anyone who copies that token is logged in as you, with no password needed.

Why would an attacker want your session cookie?

It works like your login. They become you on that site.

Words we need, 3 minutes

Vulnerability, attack, and what gets damaged

Vulnerability

A weakness in hardware, software, configuration or human behavior that an attacker can exploit.

Exploit

To use the weakness, for example to get in without permission, steal data or stop a service.

Attack vector

The route the attacker uses: an email, a web form, the Wi-Fi, an old program.

The CIA triad: the three things an attack can damage

Confidentiality

Only the right people can read the data.

Integrity

Nobody can change the data without permission.

Availability

The system works when people need it.

Every vulnerability today is labeled with what it damages most: C, I or A. Many attacks hit more than one.

Weak point 1 of 5: availability

DDoS: distributed denial of service A

What it is: many devices flood a server or network with traffic at the same time, so it runs out of capacity and real users cannot get service.

How: the attacker controls a botnet: thousands of infected devices (computers, routers, cameras, even rented cloud servers) whose owners do not know.

Distributed = from many sources. A plain DoS comes from one machine.

Real case

February 2023: Cloudflare stopped an attack peaking at 71 million requests per second, from over 30,000 IP addresses of hijacked cloud servers.

Weak point 2 of 5: data on the move

Insecure protocols and man-in-the-middle CI

Insecure network protocols

Older protocols send everything, including passwords, as plain text, with no encryption. Anyone who captures the packets can read them.

Telnet (remote control of a computer) → SSH
FTP (file transfer) → SFTP
HTTP (web pages) → HTTPS

Man-in-the-middle (MitM)

The attacker secretly sits between two devices and relays their messages. Both think they are talking directly. The attacker can read and change what passes through.

Typical route: a fake Wi-Fi hotspot called "Cafe_Free_WiFi", or a badly secured public network.

Weak point 3 of 5: people and passwords

Phishing and weak authentication C

From: IT Support <helpdesk@schooI-it-support.com>
Subject: URGENT: your password expires today

Dear user,

Your account will be closed in 2 hours. To keep your files, confirm your password now:

https://school-login.account-check.net

IT Team

Sender

"schooI" with a capital I, not the school's real domain.

Pressure

"Urgent", "2 hours": rushing you so you do not check.

Link

The real domain is account-check.net, not the school.

Request

Real IT never asks you to type your password through a link.

Phishing

A message that pretends to be from someone trusted (bank, school, delivery company) to trick a person into giving away passwords or payment details, or into opening malware. It attacks people, not machines: social engineering.

Weak authentication

Easy-to-guess, reused or default passwords (admin / admin on a router or camera), and no second check such as a phone code.

Exploited by brute force (try every option), dictionary attacks (try common passwords) and credential stuffing (try passwords leaked from another site).

Weak point 4 of 5: software, part 1

Malware: malicious software CIA

TypeWhat it does
Virusattaches to a file or program; spreads when that is run
Wormcopies itself across the network with no user action
Trojanpretends to be useful software
Ransomwareencrypts your files and demands payment
Spywaresecretly records what you do, e.g. keystrokes

How it arrives: phishing attachments, infected downloads and websites, USB drives, and flaws in software.

"invoice.pdf.exe" arrives by email. Which type?

A trojan: it pretends to be a document but is a program.

It infects one laptop, then every computer on the school network within an hour, with nobody clicking anything. Which type?

A worm: it spreads by itself.

Weak point 4 of 5: software, part 2

Unpatched software and zero-day exploits CIA

A patch is an update that fixes a flaw. Follow one flaw through its life:

Zero-dayAttackers find the flaw. The developer does not know. No patch exists.
Patch releasedThe developer learns of it and publishes a fix.
UnpatchedThe fix exists, but the device has not installed it. The flaw is now public.

Why are zero-days so dangerous?

Nobody can install a fix that does not exist, and antivirus may not recognize the attack yet.

Why is an unpatched device in more danger after the patch is released?

The patch shows everyone where the flaw is. Attackers scan the internet for devices that have not updated.

Real case: WannaCry, May 2017

A ransomware worm used a Windows flaw Microsoft had patched two months earlier. Unpatched computers, including many in the UK's NHS, were locked.

SQL injection

The attacker types SQL code into an input (login form, search box). Because the program builds its query by joining text, the input changes the meaning of the query. The database can then reveal, change or delete data.

Cross-site scripting (XSS)

The attacker posts a script into a page other people view (a comment, a review). The site shows it without checking, so it runs in every visitor's browser, for example to steal their session cookie.

Spot the difference, 4 minutes

Four pairs students mix up

Virus or worm?

A virus needs a person to run the infected file. A worm spreads across the network by itself.

Unpatched software or zero-day?

Unpatched: a fix exists but was not installed. Zero-day: no fix exists yet; the developer may not even know.

Phishing or man-in-the-middle?

Phishing tricks the person into handing data over. MitM captures data in transit; the person does nothing wrong.

SQL injection or XSS?

Both abuse user input. SQL injection attacks the database on the server; XSS runs code in other users' browsers.

SQL injection. Web application and database. C.

A forum post hides a script. Everyone who opens the thread is logged out, and their accounts start posting spam.

Attackers use a browser flaw that the browser's developer did not know about. No update exists yet.

Exam technique, 3 minutes

Naming is not describing

Describe how SQL injection could affect an online shop. [3]

Answer A

"SQL injection is when hackers attack the database and steal data."

1 mark at most: it names the effect but never says how.

Answer B

"The attacker types SQL code into an input such as the search box. The shop builds its query from that input, so the code changes what the query does. The attacker can then read every customer's details, which breaks confidentiality."

3 marks: what it is, how it is exploited, what it damages, all in the shop's context.
