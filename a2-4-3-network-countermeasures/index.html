The big idea, 4 minutes

Defense in depth

Countermeasure

A hardware, software, policy or training measure that reduces a specific vulnerability.

Defense in depth

Several layers of countermeasures, so that if one layer fails, the next one still stops the attack. No single countermeasure covers every vulnerability.

The question to ask every time

Not only "what does it protect against?" but "what does it NOT protect against?"

MFA stops stolen passwords, but does nothing against SQL injection. Input validation stops SQL injection, but does nothing against DDoS.

Data on the move 1 of 2: against man-in-the-middle and insecure protocols

Encrypted protocols and SSL/TLS certificates

Encrypted protocols

Encrypt the data in transit, so an attacker who captures the packets sees only ciphertext.

HTTP → HTTPS   Telnet → SSH   FTP → SFTP / FTPS

SSL/TLS certificate

A digital document that binds a website's public key to its domain name, signed by a trusted Certificate Authority (CA). It proves the browser is talking to the real server, not an attacker in the middle.

SSL is the old, broken protocol. TLS replaced it. People still say "SSL certificate".

The browser checks three things

1. Signed by a CA it trusts?  2. Not expired?  3. Domain name matches the one you typed? Any fail: a security warning.

    Data on the move 2 of 2: against eavesdropping on public networks

    VPNs: an encrypted tunnel

    Virtual private network (VPN)

    Creates an encrypted tunnel between your device and a VPN server (for example, the school network) across a public network. All your traffic goes through it, whatever the app.

    Used for

    Secure remote access to an organization's internal network; protecting traffic on public Wi-Fi.

    Limits

    Slower (extra encryption and a longer route); a badly configured VPN is itself a way in; you must trust whoever runs the VPN server; it does nothing against phishing or malware you download.

    TLS and a VPN both encrypt. How do they differ in scope?

    TLS: protects one connection between your browser and one website, and proves that website's identity. VPN: protects all traffic between your device and one network, for every app, and gives you access to that network's internal resources.

    A teacher marks work at an airport café. The school grading system is not on the internet at all. Which one does she need?

    A VPN: it puts her laptop "inside" the school network through the tunnel. TLS alone cannot reach an internal-only server.

    Colonial Pipeline, 2021: attackers logged in to the company VPN. What went wrong?

    The VPN account used a leaked password and had no MFA. A VPN is only as strong as the authentication in front of it. Next slide.

    Accounts: against weak authentication, phishing and stolen passwords

    Complex password policies and MFA

    Password policy calculator

    Possible passwordsTime to try them all, offline, at 10 billion guesses per second

    Complex password policy

    Organization rules: minimum length (12+), mix of character types, no dictionary or leaked passwords, no reuse, account lockout after a few failures. Modern advice (NCSC, NIST): length beats complexity; forced changes every 60 days lead to Password1 → Password2.

    Multi-factor authentication (MFA)

    Two or more different kinds of proof:

    Know
    password, PIN
    Have
    phone code, security key
    Are
    fingerprint, face

    A stolen or phished password alone is no longer enough to log in.

    Password + PIN: is that MFA?

    No. Both are something you know. MFA needs factors of different kinds.

    Web applications: against SQL injection and XSS

    Input validation and content security policies

    Input validation

    Check that input matches what the system expects before it is processed or stored.

    Whitelisting: accept only what matches an expected pattern (a phone field: digits only, 8 to 15 of them). Filtering: reject input that breaks the rules (for example, contains ' or <script>). Whitelisting is stronger: attackers find ways around a list of "bad" characters.

    Must happen on the server: an attacker can skip checks in the browser. Against SQL injection, also use prepared statements, which keep input as data, never code.

    Content Security Policy (CSP)

    An HTTP header the server sends that tells the browser which sources are allowed to load scripts, styles and images. Injected scripts from anywhere else are refused. A second layer against XSS, not a replacement for validation.

    Watching the network: against malware, brute force and unknown attacks

    IDS and IPS

    Intrusion detection system (IDS)

    Monitors traffic and alerts an administrator. Does not stop anything itself. A security camera.

    Intrusion prevention system (IPS)

    Monitors traffic and blocks it automatically: drops packets, blocks an IP address. A security guard.

    How they spot attacks

    Signature-based: matches known attack patterns. Accurate, but misses new attacks (zero-days). Anomaly-based: learns what normal looks like and flags anything unusual. Can catch new attacks, but raises false positives.

    Availability and the inbox: against DDoS, phishing and malware attachments

    DDoS mitigation tools and email filtering

    DDoS mitigation tools
    Rate limitingcaps requests per second from any one address; excess is dropped
    Traffic filtering, scrubbingremoves packets that match attack patterns; clean traffic goes on
    Load balancingspreads requests over many servers, so no single one is the bottleneck
    CDN, anycastcopies of the site in many locations; the flood is split between them
    Cloud DDoS protectiona provider absorbs the flood before it reaches your network
    Email filtering solutions
    Spam filteringscores each email on sender reputation and content
    Anti-phishingchecks the sender really owns the domain (SPF, DKIM, DMARC) and checks links against known phishing sites
    Attachment sandboxingopens attachments in an isolated space and watches what they do
    Link scanningchecks the destination again when the user clicks
    Impersonation detectionflags lookalike domains, such as schooI-it-support.com

    Last week's slider: why did blocking one address not help? Which tool fixes that?

    The flood comes from thousands of addresses. Scrubbing and cloud protection recognize the pattern across all of them; load balancing and CDNs add capacity. Limit: very large floods, and false positives that block real users.

    Why can email filtering never be the only defense against phishing?

    Filters make false negatives: a well-made phishing email gets through. Then training (spot it) and MFA (a stolen password is not enough) are the next layers.

    Software and Wi-Fi: against unpatched software, rogue devices and eavesdropping

    Software updates and wireless security

    Update software (patch management)

    Install the vendor's fixes for known flaws: operating systems, applications, firmware on routers and cameras. Organizations watch vulnerability lists (CVE), prioritize critical, internet-facing systems, test, then deploy; automatic updates where possible.

    Equifax, 2017: a web software flaw was patched in March. Equifax did not install it. Attackers used it from May; 147 million people's data was exposed.

    Limit: no help against a zero-day: there is no patch yet.

    The big limitation of MAC filtering?

    MAC spoofing: an attacker sees the MAC addresses of connected devices in the air and copies one. So it is an extra layer, never the main one.

    Wireless security measures

    WPA3 encryption of all Wi-Fi traffic (WEP and WPA2 are weaker). A strong Wi-Fi password. A separate guest network with no access to internal servers. Rogue access point detection finds fake hotspots.

    MAC address filtering: the access point checks each device's hardware (MAC) address.

    People and testing: the layers that check all the others

    Employee training and regular security testing

    Security awareness training

    Most serious incidents involve a person: a clicked link, a reused password. Training covers spotting phishing, password managers, checking requests by phone, reporting incidents fast.

    Simulated phishing: the organization sends fake phishing emails; whoever clicks gets training on the spot. Click rates fall, and the organization can measure it.

    Security testingWhat it does
    Vulnerability scanningautomated tools look for known flaws and misconfigurations; weekly or continuous
    Penetration testingauthorized ethical hackers try to break in, like a real attacker; yearly or after big changes
    Security auditreviews policies, settings, accounts and logs against the rules
    Bug bountyoutside researchers are paid to report flaws they find

    Why test regularly, not once?

    New flaws are found in existing software, the network changes, people change. Testing finds weaknesses before attackers do, and checks the real security matches what IT believes it is.

    Spot the difference, 4 minutes

    Six pairs students mix up

    IDS or IPS?

    IDS detects and alerts; a person must act. IPS detects and blocks automatically, so a false positive blocks real users.

    TLS certificate or VPN?

    TLS: one browser-to-website connection, plus proof of the site's identity. VPN: all device traffic into one network.

    Whitelist or blacklist?

    Whitelist: deny by default, allow only listed. Blacklist: allow by default, block only listed.

    Input validation or CSP?

    Validation: the server rejects bad input before using it. CSP: the browser refuses scripts from sources not on the list.

    Vulnerability scan or penetration test?

    Scan: automated search for known flaws. Pen test: people actually try to exploit them, like a real attacker.

    Signature or anomaly detection?

    Signature: matches known attacks, misses new ones. Anomaly: flags unusual behavior, catches new ones, more false positives.

    Real case, 5 minutes: Colonial Pipeline, May 2021

    Which countermeasure was missing at each stage?

    What happenedMissing countermeasure, and what it would have done
    1. The password for an old VPN account had probably leaked in an earlier breachComplex password policy with no reuse, and checking passwords against breach lists: the leaked password would not have worked.
    2. The attackers logged in to the company VPN with itMFA on the VPN: the password alone would not get them in.
    3. Ransomware spread through the IT networkIDS/IPS to spot mass file encryption; segmentation to limit how far it spread.
    4. The company shut the pipeline to protect its control systems, and paid $4.4 millionTested backups and an incident response plan: recover without paying. (The IT/control system separation is what prevented physical damage.)

    One missing layer let them in. Several missing layers let it get this bad.

    One strong answer (others can be justified)

    1. Software updates on all 20 computers: free, and known flaws are what automated attacks scan for. 2.     Exam technique, 3 minutes

    Mechanism, then the vulnerability it stops

    Explain how multi-factor authentication strengthens network security. [3]

    Answer A

    "MFA makes accounts much more secure because it adds extra security, so hackers cannot get in."

    1 mark at most: "more secure" restates the question; no mechanism, no vulnerability.

    Answer B

    "MFA adds a layer beyond the password. The user must give two different types of proof, such as a password they know and a code from a phone they have. So if the password is stolen by phishing or a leak, the attacker still cannot log in without the second factor."

    3 marks: extra layer; two different factor types, with examples; reduces the risk from stolen passwords.
